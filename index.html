Read the complete response +

FlashAttention uses tiling and recomputation to compute exact attention while reducing HBM accesses, as described in the evidence:

Tiling

Tiling splits the inputs Q, K, and V into blocks and processes them incrementally. This allows the softmax reduction to be performed without materializing the full N×NN \times N attention matrix in HBM. Specifically:

  • The inputs are divided into blocks of size Bc×dB_c \times d (for K and V) and Br×dB_r \times d (for Q).
  • The algorithm loops over blocks of K and V (outer loop) and blocks of Q (inner loop), computing partial attention scores and normalization statistics on-chip in SRAM.
  • Softmax is computed block-by-block using decomposition formulas to maintain numerical stability and avoid storing the full attention matrix FlashAttention 105–159 ↗.

Recomputation

Recomputation avoids storing the large intermediate attention matrix S (or P) in HBM for the backward pass. Instead:

  • The softmax normalization statistics (m,ℓ)(m, \ell) are stored in HBM after the forward pass.
  • During the backward pass, these statistics are used to recompute the attention matrix S and P on-chip from the block-wise Q, K, and V data in SRAM, rather than reading the full N×NN \times N matrix from HBM FlashAttention 105–159 ↗.

This combination allows FlashAttention to achieve exact attention with O(N)O(N) additional memory and sub-quadratic HBM accesses, as proven in Theorem 1 FlashAttention 105–159 ↗.

Query 3 / Local and global attentionLocal inference · Qwen3.5 4B

How does Longformer's sliding-window attention differ from its global attention? Include the original attention-pattern figures.

Answer excerpt

Sliding-window attention

This pattern employs a fixed-size window surrounding each token to capture local context. By stacking multiple layers of such windowed attention, the model builds a large receptive field where top layers can access information across the entire input, similar to CNNs Longformer 91–117 ↗.

Global attention

The sliding window and dilated attention patterns are not flexible enough to learn task-specific representations on their own. Therefore, Longformer adds "global attention" on a few pre-selected input locations to aggregate representations for tasks like classification or question answering Longformer 91–117 ↗.

Read the complete response +

Longformer's sliding-window attention and global attention differ in their scope, flexibility, and how they are configured to support different tasks.

Sliding Window Attention This pattern employs a fixed-size window surrounding each token to capture local context. By stacking multiple layers of such windowed attention, the model builds a large receptive field where top layers can access information across the entire input, similar to CNNs Longformer 91–117 ↗.

  • Configuration: Given a fixed window size ww, each token attends to 12w\frac{1}{2}w tokens on each side Longformer 91–117 ↗.
  • Dilation: To increase the receptive field without increasing computation, the window can be "dilated" (analogous to dilated CNNs), where the window has gaps of size dilation dd Longformer 91–117 ↗.
  • Complexity: The computation complexity scales linearly with input sequence length nn (O(n×w)O(n \times w)) Longformer 91–117 ↗.
  • Figure: The configuration of sliding window attention is illustrated in Figure 2(b) Longformer 51–83 ↗:

Global Attention The sliding window and dilated attention patterns are not flexible enough to learn task-specific representations on their own. Therefore, Longformer adds "global attention" on a few pre-selected input locations to aggregate representations for tasks like classification or question answering Longformer 91–117 ↗.

  • Configuration: This attention operation is symmetric: a token with global attention attends to all tokens across the sequence, and all tokens in the sequence attend to it Longformer 91–117 ↗.
  • Task Specificity: The locations for global attention are task-specific. For example, for classification, global attention is used for the [CLS] token, while for QA, it is provided on all question tokens Longformer 91–117 ↗.
  • Complexity: Since the number of tokens with global attention is small relative to and independent of nn, the complexity of the combined local and global attention remains linear (O(n)O(n)) Longformer 91–117 ↗.
  • Projections: Longformer uses two sets of projections (Qs,Ks,VsQ_s, K_s, V_s for sliding window and Qg,Kg,VgQ_g, K_g, V_g for global attention) to provide flexibility in modeling different types of attention Longformer 91–117 ↗.
  • Figure: An example of sliding window attention with global attention at a few custom locations is shown in Figure 2(d) Longformer 51–83 ↗:

Comparison Summary

  • Scope: Sliding window attention focuses on local context within a fixed or dilated window, whereas global attention connects specific tokens to the entire sequence.
  • Flexibility: Sliding window attention has a fixed structure per layer, while global attention is task-motivated and can be placed at custom locations (e.g., [CLS] or question tokens) Longformer 91–117 ↗.
  • Implementation: Sliding window attention uses projections for local heads, while global attention utilizes separate projection matrices (Qg,Kg,VgQ_g, K_g, V_g) initialized to match the sliding window projections Longformer 91–117 ↗.

The calculation remains unchanged because the algorithm uses tiling and softmax normalization factors to avoid storing the large N×NN \times N attention matrix (the "big square array") in memory while still computing the exact result.

Specifically:

  • Decoupling via Normalization Constants: The softmax normalization constant Li=∑jeqiTkjL_i = \sum_j e^{q_i^T k_j} is computed separately. Once LiL_i is known, the output oio_i can be computed by repeatedly summing terms like eqiTkjLivj\frac{e^{q_i^T k_j}}{L_i} v_j without needing the full attention matrix PP stored in memory FlashAttention 533–559 ↗.
  • Tiling: The inputs Q,K,VQ, K, V are split into blocks. The algorithm processes these blocks incrementally, computing partial softmax reductions on-chip (in SRAM) rather than materializing the full N×NN \times N matrix on slow HBM FlashAttention 105–159 ↗.
  • Recomputation: Instead of storing the intermediate attention matrix SS or PP for the backward pass, the algorithm stores the output OO and the softmax normalization statistics (m,ℓ)(m, \ell). These statistics allow the attention matrix SS and PP to be recomputed easily from the block inputs in SRAM during the backward pass, avoiding the need to store the large matrix FlashAttention 105–159 ↗.

This approach ensures that the mathematical result is identical to standard attention, but the memory footprint is reduced to O(N)O(N) instead of O(N2)O(N^2), and the large matrix is never materialized in HBM FlashAttention 17–31 ↗.

1. Setup and Usage

Configure providers

Choose a vision model for scanning and a capable extraction model for indexing. Query with the local Qwen model using the override shown below.

Scanning

Replace the provider/model placeholders with entries from your configured catalog.

docfoo auth --set PROVIDER
docfoo model --set scan PROVIDER/VISION_MODEL
Indexing and default writer

The KG slot is shared. Set the extraction model here; override the writer per query.

docfoo model --set kg PROVIDER/INDEX_MODEL
Decision model · Jev

Set OPENROUTER_API_KEY in the process environment. Merge these keys into kg-settings.json.

{
  "query": {
    "enableConceptRouting": true,
    "conceptProvider": "openrouter",
    "conceptModel": "typesafe/jev-1.13"
  }
}

For llama.cpp, merge the local provider configuration into <workspace>/.agent/models.json. Match the model ID and context window to your server. Run docfoo setup once for native scan dependencies.

Evidence settings with Jev routing ↓Local-only query settings ↓

Scan a document

Convert PDFs and images to Markdown with saved figure/table crops. Rerun the same source to resume an interrupted scan.

docfoo scan paper.pdf diagram.png --output references

Build or update a scoped graph

Extract entities, concepts and relations for one collection. Unchanged sections are skipped on later runs.

docfoo kg --index --scope references

Ask for a sourced answer

Use local Qwen3.5 4B for the answer without changing the configured extraction model. Jev is a separate hosted request; local-only settings disable it.

docfoo kg --query "Which methods reduce memory usage?" --scope references --model local/unsloth/Qwen3.5-4B-GGUF:Q4_K_M --json
