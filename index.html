What problem does DocFoo solves?

Mainly simplicity.

First we narrow down our scope to technical corpus with scientific/medical terminologies. The more your queries contain technical terms, faster the DocFoo retrieves answers for you.

DocFoo uses an embedding-free approach, is non-agentic, and makes only a single generative LLM call per query (just for writing the final, polished answer). It's evidence delivery is highly deterministic and reproducible for a fixed index, model, and configuration.

Additionally, the evidence delivery is separated from LLM writing, so you can use a very small LLM (e.g., Qwen3.5 4B) for answer writing. This plummets the operational cost significantly. Though for complex multi-hop queries, prefer using Qwen3.6 35B-A3B to prevent small model drift and more coherent answers. If all you want are the source evidences, you can even disable LLM call completely.

Engineering philosophy of DocFoo +

DocFoo is designed to be very easy to use and integrate. No complex database servers, no docker containers, no python dependency hell. Just download and run. The core is written in Rust. The framework is designed to return the actual cropped figures, tables, charts, code snippets etc., from your PDFs/images. So there's no loss of information in answers you receive.

We highly recommend you to check Pikins, a persistent multi-agent harness we built to make working with DocFoo as simple as chatting in imessage.

Comparison with similar methods +

There exist multiple RAG frameworks trying to solve a similar problem. However, structurally they often rely on embedding models (e.g., GraphRAG local search, DRIFT search, LightRAG, Neo4j’s vector-based retrievers, DeepSearcher etc.) for indexing and semantic matching, sometimes combined with keyword matching. This makes source selection less transparent, since vector similarity scores don’t directly explain why a particular excerpt was chosen over another. Or they rely on potentially multiple LLM calls to get them the right excerpts from the indexed sources (e.g., PageIndex, DRIFT search, DeepSearcher). There is also a setup friction for non-developers and most methods target enterprise needs.

    The claim is only partly correct. Longformer and BigBird sparsify the attention pattern, so they reduce attention arithmetic by omitting many token-to-token connections. FlashAttention does not drop connections: it computes exact, full attention while reducing memory use and high-bandwidth-memory (HBM) traffic. Longformer 87–87 ↗ FlashAttention 105–159 ↗

    In the original Transformer, full self-attention has O(n2)O(n^2) time and memory complexity in sequence length nn. Every token can attend directly to every other token, so the maximum attention-path length is 1. Longformer 13–39 ↗ Attention Is All You Need 117–123 ↗

    Longformer replaces full attention with local sliding-window attention plus task-selected global attention. With window width ww, each token attends to w/2w/2 tokens on each side; the local computation is O(n×w)O(n \times w), and the receptive field grows across layers. Dilation spaces out the window connections, increasing receptive field without increasing computation; for fixed dilation dd and ww, the stated receptive field is ℓ×d×w\ell \times d \times w over ℓ\ell layers. Global attention is symmetric: global tokens attend to the whole sequence, and all tokens attend to them. This supplies long-range routes, with combined local/global attention still O(n)O(n) when the number of global tokens is small and independent of nn. Longformer 91–117 ↗

    BigBird combines local-window, random, and global connections. Its global tokens can be existing tokens (ITC) or additional tokens (ETC); the paper says the added ETC tokens provide extra context storage and improve performance in experiments. Big Bird 15–41 ↗ Big Bird 97–101 ↗ Its theoretical claims are conditional: the universality result uses a sparse graph containing a star graph, and the Turing-completeness result is for a sparse attention mechanism using O(n)O(n) inner products, under the paper’s stated precision assumptions. Big Bird 718–730 ↗ Big Bird 793–799 ↗ These are expressivity guarantees, not a claim that sparse attention reproduces every full-attention computation at the same cost.

    FlashAttention instead tiles Q,K,VQ,K,V, computes attention block by block, and combines block results using normalization statistics. It avoids storing the O(N2)O(N^2) intermediate attention matrices: the paper states O(N)O(N) additional memory beyond inputs and output. For the backward pass, it recomputes attention intermediates from stored inputs, output, and statistics rather than storing them. The result remains exact, with O(N2d)O(N^2d) FLOPs; tiling and recomputation target HBM accesses, not quadratic arithmetic. FlashAttention 105–159 ↗

    So the costs differ: Longformer and BigBird reduce arithmetic by using sparse connectivity; FlashAttention preserves quadratic arithmetic and all-pairs interaction, while reducing additional memory and HBM traffic. If every token pair must still interact, use FlashAttention: it retains exact attention rather than approximating it by dropping connections. FlashAttention 105–159 ↗

    The evidence gives complexity and connectivity descriptions but does not state a numeric maximum path length for Longformer or BigBird; those depend on the specific attention pattern and layers. It also does not provide source file line ranges in a form usable here, so citations identify the evidence blocks rather than file/line ranges.

      How does FlashAttention use tiling and recomputation to compute exact attention? Show its original Figure 1.

      Answer excerpt

      FlashAttention uses tiling and recomputation to compute exact attention while reducing HBM accesses, as described in the evidence:

      • Softmax is computed block-by-block using decomposition formulas to maintain numerical stability and avoid storing the full attention matrix FlashAttention 105–159 ↗.
      • During the backward pass, these statistics are used to recompute the attention matrix S and P on-chip from the block-wise Q, K, and V data in SRAM, rather than reading the full N×NN \times N matrix from HBM FlashAttention 105–159 ↗.
      Read the complete response +

      FlashAttention uses tiling and recomputation to compute exact attention while reducing HBM accesses, as described in the evidence:

      Tiling

      Tiling splits the inputs Q, K, and V into blocks and processes them incrementally. This allows the softmax reduction to be performed without materializing the full N×NN \times N attention matrix in HBM. Specifically:

      • The inputs are divided into blocks of size Bc×dB_c \times d (for K and V) and Br×dB_r \times d (for Q).
      • The algorithm loops over blocks of K and V (outer loop) and blocks of Q (inner loop), computing partial attention scores and normalization statistics on-chip in SRAM.
      • Softmax is computed block-by-block using decomposition formulas to maintain numerical stability and avoid storing the full attention matrix FlashAttention 105–159 ↗.

      Recomputation

      Recomputation avoids storing the large intermediate attention matrix S (or P) in HBM for the backward pass. Instead:

      • The softmax normalization statistics (m,ℓ)(m, \ell) are stored in HBM after the forward pass.
      • During the backward pass, these statistics are used to recompute the attention matrix S and P on-chip from the block-wise Q, K, and V data in SRAM, rather than reading the full N×NN \times N matrix from HBM FlashAttention 105–159 ↗.

      This combination allows FlashAttention to achieve exact attention with O(N)O(N) additional memory and sub-quadratic HBM accesses, as proven in Theorem 1 FlashAttention 105–159 ↗.

      Figure 1

      The original Figure 1 from the paper is shown below:

      Caption: Left: FlashAttention uses tiling to prevent materialization of the large N×NN \times N attention matrix (dotted box) on (relatively) slow GPU HBM. In the outer loop (red arrows), FlashAttention loops through blocks of the K and V matrices and loads them to fast on-chip SRAM. In each block, FlashAttention loops over blocks of Q matrix (blue arrows), loading them to SRAM, and writing the output of the attention computation back to HBM.       Query 3 / Local and global attentionLocal inference · Qwen3.5 4B

      How does Longformer's sliding-window attention differ from its global attention? Include the original attention-pattern figures.

      Answer excerpt

      Sliding-window attention

      This pattern employs a fixed-size window surrounding each token to capture local context. By stacking multiple layers of such windowed attention, the model builds a large receptive field where top layers can access information across the entire input, similar to CNNs Longformer 91–117 ↗.

      Global attention

      The sliding window and dilated attention patterns are not flexible enough to learn task-specific representations on their own. Therefore, Longformer adds "global attention" on a few pre-selected input locations to aggregate representations for tasks like classification or question answering Longformer 91–117 ↗.

      Read the complete response +

      Longformer's sliding-window attention and global attention differ in their scope, flexibility, and how they are configured to support different tasks.

      Sliding Window Attention This pattern employs a fixed-size window surrounding each token to capture local context. By stacking multiple layers of such windowed attention, the model builds a large receptive field where top layers can access information across the entire input, similar to CNNs Longformer 91–117 ↗.

      • Configuration: Given a fixed window size ww, each token attends to 12w\frac{1}{2}w tokens on each side Longformer 91–117 ↗.
      • Dilation: To increase the receptive field without increasing computation, the window can be "dilated" (analogous to dilated CNNs), where the window has gaps of size dilation dd Longformer 91–117 ↗.
      • Complexity: The computation complexity scales linearly with input sequence length nn (O(n×w)O(n \times w)) Longformer 91–117 ↗.
      • Figure: The configuration of sliding window attention is illustrated in Figure 2(b) Longformer 51–83 ↗:

      Global Attention The sliding window and dilated attention patterns are not flexible enough to learn task-specific representations on their own. Therefore, Longformer adds "global attention" on a few pre-selected input locations to aggregate representations for tasks like classification or question answering Longformer 91–117 ↗.

      • Configuration: This attention operation is symmetric: a token with global attention attends to all tokens across the sequence, and all tokens in the sequence attend to it Longformer 91–117 ↗.
      • Task Specificity: The locations for global attention are task-specific. For example, for classification, global attention is used for the [CLS] token, while for QA, it is provided on all question tokens Longformer 91–117 ↗.
      • Complexity: Since the number of tokens with global attention is small relative to and independent of nn, the complexity of the combined local and global attention remains linear (O(n)O(n)) Longformer 91–117 ↗.
      • Projections: Longformer uses two sets of projections (Qs,Ks,VsQ_s, K_s, V_s for sliding window and Qg,Kg,VgQ_g, K_g, V_g for global attention) to provide flexibility in modeling different types of attention Longformer 91–117 ↗.
      • Figure: An example of sliding window attention with global attention at a few custom locations is shown in Figure 2(d) Longformer 51–83 ↗:

      Comparison Summary

      • Scope: Sliding window attention focuses on local context within a fixed or dilated window, whereas global attention connects specific tokens to the entire sequence.
      • Flexibility: Sliding window attention has a fixed structure per layer, while global attention is task-motivated and can be placed at custom locations (e.g., [CLS] or question tokens) Longformer 91–117 ↗.
      • Implementation: Sliding window attention uses projections for local heads, while global attention utilizes separate projection matrices (Qg,Kg,VgQ_g, K_g, V_g) initialized to match the sliding window projections Longformer 91–117 ↗.
